# PerpsVault deployment (owner-run; NOT to be run now)

**STATUS: PROTOTYPE, UNAUDITED. The perpetuals are not deployed before an external audit and legal review
(BRIEF-ROUND18 rule 3).** This page says what the owner would run, and what was rehearsed.

## Prerequisites (all owner inputs)

1. The Bloch L2 (chain 700770) is live and bUSDC (the Ethereum route's `BridgedStablecoinV3`) is deployed there; its
   address goes into `token` and the keccak256 of its runtime code (`cast codehash <token> --rpc-url <L2 RPC>`,
   compared with the bridge's reviewed deployment record) into `tokenCodehash` (both `TBD-deploy` today). The script
   refuses a token whose runtime code differs from the pin (round 2; the bridge's custody preflight pins the token
   runtime the same way).
2. Seven validator addresses and three guardian addresses, each generated by its holder on its own hardware or
   offline machine (never by an agent), collected and checked as in the bridge key ceremony
   (bloch-l2-bridge `docs/BRIDGE-V3-KEY-CEREMONY.md`). They replace the `TBD-owner` entries.
3. The limits of `deploy/vault.config.json` confirmed or changed (cap, window, large threshold and delay, forced
   and escape delays, pause duration and cooldown). `feeRecipient` is fixed to
   `0x775a993F09Bd80aeCF8F8c2ADe0C84158E3a0544`; the script refuses any other value.
4. A deployer key with about 0.005 L2 ETH equivalent of gas (a plain hot key used once, or a Ledger; it gets no
   power over the vault: the vault has no owner).
5. A build of this commit: from `contracts/`, `forge build`.

## Commands (one per block, from `contracts/`)

Pre gate and deployment in one step (the script prints every value, refuses `TBD`, a wrong chain id, a wrong fee
recipient, a token whose runtime code is not the pinned one, and after the deployment checks the vault's runtime code
against a twin built from the same config in the script's simulation (never sent; R436-9), every immutable and the
committee):

```
VAULT_CONFIG=deploy/vault.config.json forge script script/DeployPerpsVault.s.sol --rpc-url TBD-L2-RPC --ledger --broadcast
```

Post gate, read-only, against a second, independent RPC endpoint, after the deployment block is final on the L2
(replace the address with the one printed). It proves the address holds THIS build's code with THIS config, not only
that it answers the getters:

```
VAULT=TBD-vault-address MODE=check VAULT_CONFIG=deploy/vault.config.json forge script script/DeployPerpsVault.s.sol --rpc-url TBD-second-L2-RPC
```

Then: record the vault address in the engine genesis (`verifyingContract`, SPEC 2.1 and 10) and in the node
configuration; the frontend pins it at build time (SPEC 2.1).

If the deployment transaction fails: nothing exists, fix and rerun. If it succeeds but the post gate fails: do not
use that vault (it has no funds and no owner; abandon it) and deploy again.

## Local stack deployment (round 2; private anvil only, never a real network)

`script/local_deploy.py` deploys `src/dev/MockBUSDC.sol` (6 decimals, open faucet, no value) and `PerpsVault` with a
5-of-7 committee and 3 guardians on a private anvil, for the local full stack (node 431, frontend 434, e2e 435).
It refuses a non-loopback RPC, an RPC that does not answer `anvil_nodeInfo`, a chain id other than `--chain-id`
(default 700770), and an output directory that git would track when it has to generate keys. It takes no private
key: transactions go from anvil's unlocked dev account. The committee is either passed in (`--validators`, seven
addresses of the node's throwaway committee; `--guardians`, three) or generated at run time with `cast wallet new`
into `<out>/throwaway-keys.json` (mode 0600; `deploy/local/` is git-ignored).

Start anvil (loopback, chain id 700770; ports 49700-49799 are agent 433's, 435 uses its own):

```
anvil --host 127.0.0.1 --port 49700 --chain-id 700770
```

Deploy (from `contracts/`):

```
python3 script/local_deploy.py --rpc http://127.0.0.1:49700 --out deploy/local --validators 0xV1,0xV2,0xV3,0xV4,0xV5,0xV6,0xV7 --fund 0xUSER
```

One-command form for the stack (435): `deploy/local.sh <rpc-url> <committee.json> <out.json>` with
`committee.json = {"validators": [7], "threshold": 5, "guardians": [3] (optional)}`; `out.json` holds `chainId`,
`token`, `vault`, `deployBlock`, `committee`, `threshold`, `forcedDelay`, `escapeDelay`, `largeDelay` and
`abi: {vault: [...], token: [...]}` (the ABI arrays themselves). Foundry is taken from `$FOUNDRY_DIR`,
`~/.local/share/dex-tools/foundry`, `~/.foundry/bin` or `PATH`.

Output in `--out`: `deployment.json` (schema `postern-perps/local-deployment/1`: `token`, `vault`,
`vaultDeployBlock`, `chainId`, `validators`, `guardians`, `limits`, `eip712Domain`, `domainSeparator`,
`depositHead0`, `forcedHead0`, `gasUsed`), `PerpsVault.abi.json`, `MockBUSDC.abi.json`; the same JSON on stdout,
last line `LOCAL-DEPLOY OK <vault> <token>`. On a fresh anvil the addresses are always token
`0x5FbDB2315678afecb367f032d93F642f64180aa3` and vault `0xe7f1725E7734CE288F8367e1Bb143E90bb3F0512` (deployer nonces
0 and 1). Limits default to the proposal of `deploy/vault.config.json`; `--set forcedDelay=86400` style overrides
stay inside the constructor's bounds (a rehearsal passes the delays with `evm_increaseTime`, it does not shrink
them). The committed ABI files `abi/PerpsVault.abi.json` and `abi/MockBUSDC.abi.json` are written by
`python3 script/export_abi.py` and compared with the build by `python3 script/export_abi.py --check`.

Rehearsed 2026-11-18 (agent 433, anvil 1.7.1 on 127.0.0.1:49700): deployment and post gate pass (vault creation
4,934,833 gas as an anvil transaction, token 390,403); refusals shown for a non-loopback RPC, a dead RPC, a wrong
chain id, `forcedDelay=60` (constructor `InvalidConfiguration`) and a tracked output directory.

## End-to-end replay on anvil (round 2)

`python3 script/e2e_anvil.py [--port 49710] [--out evidence.json]` starts one fresh anvil per story of
`test/vectors/engine/`, deploys the token and the vault at the address the engine vectors were signed for, sends every
step as a transaction at its L2 timestamp, checks every expected effect and refusal, records gas, and stops the anvil
it started. Result 2026-11-18: 4 stories PASS (85 steps, 178 checks, 36 refusals); `docs/VAULT.md` sections 9 and 10a.
